# medistruct-audit

Code and results for the manuscript *Evidence Grounding, Roundtrip Consistency, and Agentic Quality Assurance in Local Clinical Note Structuring*.

**Status:** manuscript under coauthor review. The preprint link and citation details will be added after posting.

**What this repository contains.** This repository distributes research source code, synthetic evaluation fixtures, synthetic run-level scores, and aggregate research results. It does not distribute restricted MIMIC-IV-Note clinical notes, patient-level extraction outputs, reference annotations, or restricted patient-level derivatives. See [docs/DATA_ACCESS.md](docs/DATA_ACCESS.md).

## What the study did

The study has two complementary experiments.

**Part A: clinical information extraction (March 2026).**
- **Data:** MIMIC-IV-Note v2.2, `discharge` table. The first 5,000 discharge-summary rows in local file order, from 2,249 patients. This is a convenience sample with no random sampling.
- **Model:** Qwen2.5-7B-Instruct, served locally with vLLM 0.16.0. It extracted symptoms, diagnoses, medications and an assessment summary under a JSON schema; every note received a hash-stamped receipt.
- **Validity:** 4,994 of 5,000 outputs were schema-valid (99.88%).
- **Evaluations:**
  - post-hoc evidence grounding and lexical support (verbatim presence of extracted items);
  - agreement with a **non-blind, collaborator-supplied 50-note reference set**, compared with a rule-based baseline;
  - structured → text → structured roundtrip self-consistency on the same 50 notes.
- **Evidence spans:** these were attached **after** extraction by first-occurrence string matching (capped at 12 per note), not generated by the model. Their apparent validity is therefore largely guaranteed by construction; the manuscript analyses how the cap and the denominator choices change the evidence metrics.

**Part B: agentic quality assurance (November 2026).**
- An OpenClaw 2026.11.6 agent, driven by a locally served Qwen3.5-122B-A10B-FP8 model, audits *saved* research artifacts through twelve deterministic, read-only audit tools. The tools are exposed over the Model Context Protocol (MCP), and the tool server runs under Linux Landlock.
- It was compared on frozen held-out tasks with:
  - a deterministic checklist that uses the same twelve tools;
  - the same agent without substantive audit tools (case inventory and reported claims only).
- **Primary analysis:** 28 held-out synthetic tasks over 18 synthetic cases (14 with planted faults, 4 clean): 18 full-case audits and 10 focused questions. A 29th executed task (T29, a pilot case without verified provenance) is excluded; its results are kept only as archived aggregates (see below).
- **Finding:** the deterministic checklist was more accurate than the agent at recovering the complete fault set. The agent used fewer tool calls on some focused questions.
- **Scope:** these are synthetic audits of research artifacts with a predefined fault taxonomy. They do not demonstrate clinical deployment readiness or real-world clinical auditing performance.

**The two models had different roles.** Qwen2.5-7B-Instruct performed the clinical extraction and the roundtrip. Qwen3.5-122B-A10B only drove the audit agent over saved artifacts and synthetic cases. They are not compared as competing clinical extraction models.

**What the audit agent sees.** The deterministic audit tools may read the case-specific artifacts registered for the case under audit, which for a real case can include extraction views and source notes, in order to compute measurements. The language model receives only the tools' structured outputs: counts, rates, record identifiers, hashes, file paths, prompt or code lines, and provenance metadata. It does not receive note text. Details and limits are in [docs/DATA_ACCESS.md](docs/DATA_ACCESS.md) and [docs/SECURITY.md](docs/SECURITY.md).

## Primary results (28 synthetic held-out tasks, scoring v2)

| Metric (mean over 28 tasks) | Deterministic checklist | OpenClaw with audit tools | OpenClaw without audit tools |
|---|---:|---:|---:|
| Task F1 | 0.962 | 0.876 | 0.350 |
| Exact finding-set match | 0.929 | 0.667 | 0.202 |
| Pooled micro-F1 | 0.982 | 0.863 | 0.341 |

Paired differences (OpenClaw with audit tools − checklist; 95% task-bootstrap CI):
- task F1: −0.085 [−0.184, 0.020];
- exact match: −0.262 [−0.429, −0.095].

**Provenance of these numbers:**
- Source: [`part_b_agentic_audit/manuscript/corrected_28_tasks/`](part_b_agentic_audit/manuscript/corrected_28_tasks/README.md), regenerated from the released run-level scores.
- Task T29, an audit of a ten-note pilot case, is excluded because the pilot's provenance could not be verified.
- **Scoring v2 fixes a defect in the first release.** Runs that detected none of a task's faults had undefined task F1 and were silently dropped; they now score 0.
- The original 29-task v1 summary is kept unchanged in `part_b_agentic_audit/runs/EXP_heldout/scores_summary.json`.

## Installation (Linux, Python 3.11–3.13)

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements/extraction.txt      # Part A client side
pip install -r requirements/agentic.txt         # Part B tools, MCP server, tests
# optional baselines: pip install -r requirements/extraction-baselines-optional.txt
```

- **Model serving:** a GPU server with vLLM is needed separately; it is not installed by these files. See `requirements/vllm-server-historical.txt` and `docs/REPRODUCIBILITY.md`.
- **Part B:** additionally needs Node.js ≥ 24.16 (24.22.3 was used) and OpenClaw 2026.11.6 (`part_b_agentic_audit/environment/openclaw_npm/package.json`).

## Tests (CPU only, no data, no GPU)

```bash
python -m pytest -q tests                                  # Part A smoke tests (synthetic text)
cd part_b_agentic_audit
python -m pytest -q tests/test_audit_core.py tests/test_scoring_regression.py   # audit tools; scoring v2 regressions
python evaluation/tasks/build_tasks.py                     # generate the synthetic cases (not stored in git) + task sets
python tests/test_sandbox_mcp.py H02 H01                   # Landlock sandbox + MCP (Linux >= 6.7)

```

## Running on your own authorised data

1. **Extraction (Part A).** Serve a model behind a **local** OpenAI-compatible endpoint, then run:
   ```bash
   export OPENAI_BASE_URL=http://127.0.0.1:<port>/v1 OPENAI_API_KEY=EMPTY
   cd part_a_extraction/Codes
   python mimic_discharge_loader.py --input /path/to/your/discharge.csv.gz --out ../../data_local/inputs_5k.jsonl --limit 5000
   python run_extract.py --inputs ../../data_local/inputs_5k.jsonl --out_dir ../../data_local/extract_run \
     --schema configs/schema_v2_spans.json --prompt prompts/extract_discharge_v2.txt --model Qwen/Qwen2.5-7B-Instruct
   ```
   Clinical text must only be sent to an endpoint you control. Never point `OPENAI_BASE_URL` at a third-party service when processing MIMIC data (see docs/DATA_ACCESS.md).
2. **Roundtrip.** `run_roundtrip_vllm.py` followed by `roundtrip_eval.py`. Commands are in docs/REPRODUCIBILITY.md.
3. **Agentic audit (Part B).** Generate cases and tasks, serve an agent model with tool calling, then run `agents/run_agent.py`. Commands are in docs/REPRODUCIBILITY.md.

## Known limitations

- **Restricted experiments:** they cannot be reproduced end to end without MIMIC-IV-Note access. Some historical metadata was not retained (docs/REPRODUCIBILITY.md).
- **Sample and reference set:**
  - the extraction cohort is a non-random sequence of 5,000 notes from a local MIMIC-IV-Note copy whose acquisition manifest was not preserved;
  - the 50-note reference set was not blinded, and its annotation procedure and inter-rater reliability are not documented;
  - its matching is lexical, not clinician-adjudicated.
- **Synthetic audit evaluation:**
  - one agent model, a predefined fault taxonomy and synthetic cases;
  - several held-out tasks share a synthetic case, and the task-level bootstrap does not model that dependence;
  - the checklist was designed around known fault types and is a strong task-specific comparator.
- **Reconstructed script:** `reconstructed/gold50_micro_summary.py` is a reconstruction and is not claimed to be identical to the lost original.
- **Excluded held-out task:** task T29 audits a ten-note pilot case whose provenance could not be verified. It is excluded from the primary analysis and cannot be run from this release. It remains in the task manifest so that task numbering is unchanged.
- **Agent re-scoring from raw runs:** this needs the saved agent run directories, which are not distributed. The released run-level scores reproduce the aggregate results exactly.
- **Roundtrip comparability:** the original extraction used JSON-schema-constrained decoding (500 output tokens; 400 in one retry pass). The roundtrip re-extraction used unconstrained chat output (1,100 tokens) with a prompt that cannot be uniquely identified among three compatible templates. These differences can affect measured roundtrip consistency.
